# HoshinoOS Pi 5 — development snapshot 2026-11-07

Bootable full-disk image for **Raspberry Pi 5, USB SSD boot**. This is an
experimental integration snapshot, not a stable daily-use release.

## Download the OS image

Download both numbered files and keep them together:

- `HoshinoOS-Pi5-20261107.img.zst.001` — 1,992,294,400bytes.
- `HoshinoOS-Pi5-20261107.img.zst.002` — 704,691,672bytes.
- `SHA256SUMS`, `assets.json` and `HoshinoOS-Pi5-20261107.release.json`.

The total compressed download is about2.51GiB. Each part is below GitHub's
2GiB asset limit. GitHub's automatic **Source code** archives contain developer
scripts, not the bootable image.

On Linux, from the download directory:

```bash
sha256sum -c SHA256SUMS
cat HoshinoOS-Pi5-20261107.img.zst.001 HoshinoOS-Pi5-20261107.img.zst.002 \
  | zstd -d -o HoshinoOS-Pi5-20261107.img
```

The raw image is15,360,000,000bytes; use an SSD with at least that capacity.
Follow the [installation/flash guide](https://github.com/minhvmware/alos-on-pi/blob/v0.1.0-dev.20261107/docs/INSTALL.md)
to identify the target, preview and explicitly flash it. The same guide covers
growing userdata to use the rest of a larger SSD. Flashing erases the target.

## Included

- Aluminium Android17/API37 desktop/framework on Pi5 Linux6.18.26 and the
  Raspberry Vanilla vendor/BSP with Mesa26.1.4 V3D/V3DV.
- Task Manager serviceability provider preinstalled so factory reset retains it.
- Graphics allocator and audio/codec FMQ policy fixes, corrected labels,
  Bluetooth boot configuration and desktop boot default.
- CPU schedutil, unchanged1.5–2.4GHz limits; no voltage/GPU-clock override.
- Fresh data and metadata, compact persistent USB disk layout.

## Validation level — read before flashing

The underlying installation's desktop, Wi-Fi, USB input, Task Manager,
Bluetooth uptime and native Vulkan queue/readback plus Android swapchain
presentation were tested on Pi5. YouTube had a successful user video replay.

This download was then assembled from that SSD after factory reset. It has
fresh data/metadata, reconstructed boot FAT and the personal SSH endpoint
removed; the copy explicitly requests SELinux enforcing. **The assembled image
and original first-run setup have not received a separate physical boot test.**
This is why the release is marked prerelease.

Completed offline checks: all five embedded filesystems, empty data/metadata,
personal SSH path removal, allocated-block/private-key checks, reset-safe
provider/defaults, complete multipart zstd validation and compressed-file
digests. New host policy bootstrap reproduced the tested M12 CIL/cache digest.
Pending system journal replay was processed on the copy and the journal
recreated empty; no recovery/orphan flags or fsck warnings remain.
No full upstream Android source build is claimed.

## Fresh setup and limitations

- Complete the original Google/Aluminium setup and reconnect networking.
  No accounts, Wi-Fi credentials, old app profiles or maintainer SSH keys
  are included. The public image does not start a preconfigured SSH server.
- Userdata-held app updates/settings were erased. Check the installed Chrome
  version, then follow the documented hardware GLES workaround where needed:
  [first-boot/app guide](https://github.com/minhvmware/alos-on-pi/blob/v0.1.0-dev.20261107/docs/FIRST_BOOT.md).
- Chrome ANGLE Vulkan ES3 remains incompatible with a reported V3DV capability;
  native Vulkan success is not Chrome Vulkan or game/conformance certification.
- Startup/launcher/app ANRs, TikTok performance, Bluetooth pairing/audio,
  hardware video/audio/camera coverage, suspend, NVMe, production AVB/OTA and
  final branding/Pixel integration remain incomplete.
- The source SSD negotiated USB2 even with the reported USB3 connection.
  CPU tuning has not established a measured responsiveness gain.

Developer inputs, metadata repair, UART, optional fresh-key SSH and packaging
commands are in the [developer guide](https://github.com/minhvmware/alos-on-pi/blob/v0.1.0-dev.20261107/docs/DEVELOPMENT.md).
